# Lesson printable formats — analyzer integration spec

## Goal

Offer two reusable outputs for any analyzed lesson:

1. **Lesson Step Table**: a concise, printable three-column guide (`Step`, `Position`, `Instructions`) for practicing or teaching.
2. **Annotated Step Transcript**: an editable, printable DOCX containing the same groups and steps, with a brief italic summary, selected verbatim phrases, and the complete step-assigned transcript.

Both outputs must come from one versioned lesson-print model so their step numbers, group boundaries, positions, and summaries agree. The analyzer should prepare the model; renderers should handle HTML and DOCX layout. No new media download or transcription is part of this feature.

## Existing data and integration point

The current decomposition (`:decompose_v3`) supplies ordered groups and steps, each step's `instruction`, and its segment range/IDs. It has no per-step position. `pass_0.segments` supplies transcript text by segment ID. `spatial_v3` supplies each step's position (`position`, `action`), and is a prerequisite for printing. The existing `/api/lesson/{document_id}/combined` response already exposes groups, steps, positions, and segment text; `/lesson/{document_id}/print` currently renders a numbered list and will be removed as part of this change.

Add a **`print_prep`** step with `decompose` and `spatial_v3` as its DAG dependencies (owner decision, 2026-10-21; an earlier draft used `decompose` alone). It uses each step's `spatial_v3` position and its complete assigned transcript to write a concise print position, summary, and quote references. Both inputs are declared, so a change to either marks the print model stale. Lessons without `spatial_v3` need that step run first; on the Astra profile it costs nothing but time. The step returns structured data, not HTML or DOCX. Rendering and validation are deterministic. Cache the prepared result by document, transcript hash, decomposition version, prompt/schema version, and provider where applicable. The step must follow the analyzer's per-document permission gate and must not trigger analysis for an ungated document.

## Canonical print model

The names below are a proposed contract; implementation may adapt them to the project's schema conventions.

```json
{
  "schema_version": 1,
  "document_id": "uuid",
  "title": "Stored lesson title",
  "teacher": null,
  "lesson_date": null,
  "source_label": null,
  "source_url": null,
  "transcript_hash": "hash of the stored source text",
  "groups": [
    {"group_number": 1, "label": "...", "step_numbers": [1, 2]}
  ],
  "steps": [
    {
      "step_number": 1,
      "group_number": 1,
      "position": "On back; feet standing",
      "brief_summary": "Stand the feet and notice how their placement changes your support.",
      "notable_quotes": [
        {"segment_id": 12, "start_offset": 0, "end_offset": 73}
      ],
      "segment_ids": [10, 11, 12]
    }
  ],
  "editorial_notes": []
}
```

- `groups`, their labels, `step_number`, `group_number`, and `segment_ids` come from the stored decomposition and are immutable in print preparation. Never renumber, merge, omit, or invent steps. Preserve rest/scan steps and the final standing/walking transition.
- `position` is a short, human-readable configuration condensed from the step's `spatial_v3` position, corrected only where the step's own transcript clearly says otherwise. Retain side and orientation. If genuinely unknown, leave it empty rather than guess. If a step moves between positions, name both in order.
- `brief_summary` is an actionable paraphrase, normally one or two sentences. It identifies the movement, direction, alternation, and essential observation without changing the lesson's instruction. For a rest, describe the rest or scan. This is the table's `Instructions` cell and the italic line in the transcript document.
- `notable_quotes` contains zero to seven exact excerpts from the assigned transcript. Usually select five to seven for a substantial step; select fewer for brief rests or sparse text. An excerpt must be a contiguous substring of one assigned segment. Store segment ID and character offsets, not a separately rewritten quote string. Prefer memorable movement directions, sensory questions, images, and distinctions over filler. Preserve source spelling, grammar, capitalization, and punctuation; do not silently clean transcript errors. Duplicate or overlapping excerpts within a step should be rejected.
- `teacher`, date, and source metadata are optional and must be labeled only when supported by stored metadata. Do not infer them from a title unless marked as inferred. A missing field is omitted from display.
- `editorial_notes` records a material ambiguity or a deliberate interpretation that readers should see below the table. Minor transcription quirks do not need a note.

The full transcript is **not** regenerated by the LLM or stored again in this model. At export time, reconstruct each step's text from its ordered segment IDs and the stored `pass_0` segments. This keeps the document anchored to the source and prevents an LLM from dropping or changing words.

## Output A: Lesson Step Table

- Self-contained HTML that opens and prints offline; no runtime API fetch after export.
- Page title, available teacher/date/source metadata, and a short indication that this is a concise lesson guide.
- One table with exactly three columns: **Step**, **Position**, **Instructions**.
- A full-width section row for each source group, in source order. Each numbered step appears exactly once under its group. No separate quote column.
- Concise, actionable instruction text from `brief_summary`. Keep side, limb, direction, same-versus-opposite coordination, and meaningful pauses. Avoid unsupported movement details.
- If `editorial_notes` is nonempty, show a short note beneath the table.
- Letter-size portrait print CSS with readable type, repeated table header, sensible margins, section rows kept with the next row where practical, and step rows kept together where practical. A `Print / Save as PDF` button is visible on screen and hidden in print. Escape all content before insertion into HTML.

## Output B: Annotated Step Transcript

- Editable `.docx` compatible with LibreOffice Writer; letter-size pages and readable print typography.
- Title and supported metadata, then group headings in source order.
- Each step has, in this order: `Step N` heading; `brief_summary` in italics immediately below; a bulleted list of selected exact-source phrases; a bold **Transcript** label; then **all** transcript text assigned to that step.
- Keep group and step headings with their first content paragraph where practical. Do not force each step onto a new page.
- The transcript may be reflowed into short, unindented paragraphs of roughly three sentences, with one blank line between paragraphs. Paragraph boundaries are editorial only: after removing layout-only blank paragraphs, concatenating the emitted paragraph text must recover the assembled step text exactly (or by a documented Unicode-normalized equivalence if the DOCX library requires it). Do not grammar-edit, summarize, silently delete class chatter, or deduplicate repetitions.
- Display quotation marks around notable phrases if desired, but those marks are layout decoration; the excerpt itself remains source-exact.

## Validation and failure behavior

Reject preparation or export with an actionable error if any of these fail:

1. Group step-number lists and the step array disagree; steps are missing, repeated, or out of order.
2. Any segment ID is missing, assigned to two steps, or absent from the lesson's step assignment. The combined ordered IDs must cover the stored `pass_0` segment set exactly once. If legacy decomposition has gaps or overlaps, surface that as a data-quality error rather than silently producing a “full transcript.”
3. A notable excerpt's offsets do not point to a nonempty exact substring of a segment assigned to that step, or a step has more than seven excerpts.
4. A summary or position contradicts a known side, direction, or movement in the assigned source. This last check may be a review warning when it cannot be determined automatically.

If only an optional metadata field is missing, continue with the available source data. If quote selection fails, the table can still export; the annotated document can export with an empty quote list for the affected step only if the user is shown a warning. Never claim that a document contains the full transcript when coverage validation failed.

## Analyzer and UI behavior

- Register a versioned `print_prep` result in the live `analysis_step` table, per analysis profile, with `decompose` and `spatial_v3` in `depends_on`.
- Expose the prepared model through a read-only lesson API subject to the same document access checks as the lesson route.
- Offer two clearly named actions in the lesson UI: **Lesson Step Table** (HTML/print) and **Annotated Step Transcript** (DOCX download). Remove the old `/lesson/{document_id}/print` list implementation; update or redirect existing links deliberately and test them.
- No print action should silently launch a costly analysis. If preparation is not cached/current, tell the user what analysis is needed and provide the existing opt-in path.
- Include schema/prompt version and source hashes with the prepared result. On upstream change, mark it stale via the pipeline's normal dependency mechanism. Do not serve stale notes as current without an explicit label.
- Authorize access before returning transcript text or a DOCX. Offline HTML exports must contain only content the requester is allowed to access.

## Acceptance criteria

1. For a fully analyzed lesson, both formats show the same title, groups, step numbers, positions, and brief summaries in the same order.
2. Table headers are `Step`, `Position`, `Instructions`; the HTML prints on letter paper with repeated headers and no visible button.
3. Every displayed quote matches a substring of a segment assigned to its step; no step has more than seven and short rests are not padded.
4. Every stored transcript segment appears once, and only once, in the DOCX's transcript sections. Paragraphing changes neither wording nor sequence.
5. A lesson with absent optional teacher/date/spatial data still exports truthfully; a lesson with segment gaps fails the full-transcript export with a clear error.
6. DOCX opens in LibreOffice, remains editable, and passes rendered-page inspection; HTML is readable offline and passes print preview inspection.
7. Existing lesson access controls and analysis gates apply to the new endpoints and actions.
8. A new `spatial_v3` or decomposition result marks the lesson's `print_prep` stale through the normal dependency mechanism; a stale model is labeled as such.

## Model qualification

Run `gemini-3-flash` and `gpt-6-astra` (low) through the same versioned `print_prep` prompt and schema on the reference lesson and at least two varied lessons. The first trial (2026-10-21) runs Astra on 22 lessons, because Astra costs nothing per lesson. Do not infer adequacy from the model used for the hand-made reference alone. Review every step for side, position, direction, coordination, rest/transition preservation, and summary usefulness; validate quote IDs and offsets mechanically, then assess whether the selected quotes are distinctive and useful. Track truncation, correction count, latency, and cost. Use the canonical profile's model if it meets the agreed quality bar; choose a stronger default only if the comparison shows material errors that the stronger model fixes. Record model/provider provenance in the cached result and do not silently mix providers within one profile.

## Related position-embedding dependency

`embed_positions` currently declares `spatial` as its dependency, reads `spatial_v3` when available, and otherwise falls back to `spatial`. Keep that dependency while the fallback exists; changing it to `spatial_v3` alone would block lessons that only have `spatial`. The `spatial_v3` runner manually marks `embed_positions` stale after a successful run. In the profile-aware schema this update must include the active `profile_key`: the current worker SQL filters by `document_id` and `step_name` only, so a result in one profile can mark the other profile's embedding stale. When `spatial_v3` is required and backfilled, make it the declared dependency and remove the fallback and manual invalidation.

## Reference example

Lesson `87a5462f-8799-4cd3-ac5e-1b9611d1ebd7` has a 24-step, seven-group version of both formats. Use it as a visual and content-order fixture, not as a hard-coded template for step count or group count. The table and DOCX should be reproducible from the same validated print model.
